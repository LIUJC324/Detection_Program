# 前端 YOLO-OBB 后处理核对清单（2026-04-16）

本文档用于给前端同学核对当前 `YOLO-OBB stage2` 模型接入是否正确，重点解决：

- 为什么原始输出会出现 `8400`
- 为什么筛选后仍可能还有几百到上千个框
- 前端后处理应按什么口径做

当前口径对应：

- 模型类型：`YOLO-OBB`
- 输入尺寸：`640 x 640`
- 类别数：`5`
- 类别顺序：
  - `car`
  - `truck`
  - `bus`
  - `van`
  - `freight_car`
- ONNX 输入名：`images`
- ONNX 输出名：`output0`

## 1. 先确认的事实

### 1.1 `8400` 不是最终框数

如果输入尺寸是 `640`，三层检测特征图的候选位置数通常是：

- `80 x 80 = 6400`
- `40 x 40 = 1600`
- `20 x 20 = 400`

总数就是：

- `8400`

所以：

- 看到 `8400` 说明前端拿到了“原始候选输出”
- 不说明模型真的预测了 `8400` 个最终框

### 1.2 如果 NMS 后还有 `1925`，基本说明后处理口径有问题

正常情况下，按 `YOLO-OBB` 正确解码并做阈值筛选和 NMS 后，不应该还剩接近两千个最终框。

如果仍有 `1925`，优先怀疑：

1. 没有正确取 `max class score`
2. 把多个类别分数都当成独立框
3. 没有先把 `output0` 转置到正确维度
4. `xywhr / angle` 解码错了
5. NMS 作用在错误坐标上
6. 阈值过低

---

## 2. 必做检查

### 检查 1：打印原始输出形状

前端拿到 `output0` 后，第一步必须打印形状。

重点看是否类似下面两种之一：

1. `[1, 10, 8400]`
2. `[1, 8400, 10]`

这里的 `10` 预计表示：

- `5` 个框参数：`cx, cy, w, h, angle`
- `5` 个类别分数

如果不是这两种形状，前端当前使用的模型文件很可能不是这版。

### 检查 2：如果是 `[1, 10, 8400]`，先转置

如果输出是：

- `[1, 10, 8400]`

则前端后处理前应先转成：

- `[8400, 10]`

再逐候选处理。

不能直接把第二维或第三维当成框列表去解。

### 检查 3：每个候选只能保留一个类别

对每个候选，只能做：

1. 取类别分数数组
2. 求 `argmax`
3. 取这个最大类别分数作为 `confidence`
4. 只生成一个候选框

不能把一个候选的 5 个类别分数都当成 5 个框。

如果前端按“每类一框”展开，数量会直接爆炸。

### 检查 4：确认有没有单独的 objectness

这版配置按 Ultralytics `YOLO-OBB` 的常见导出习惯，假设每个候选是：

- `cx, cy, w, h, angle, cls0, cls1, cls2, cls3, cls4`

也就是：

- 没有单独 `objectness`
- 置信度直接取 `max(class_scores)`

如果前端还在按旧 YOLO 公式：

- `obj * cls_score`

来算，结果也会错。

### 检查 5：NMS 前必须先解成真正的框

前端不能把原始通道值直接拿去做 NMS。

必须先把每个候选解成真实框表示，例如：

- `xywhr`
  或
- `polygon`

之后再做 NMS。

如果直接拿原始输出数组前几维当 `x1,y1,x2,y2` 去做 NMS，数量一般压不下来。

### 检查 6：确认角度单位

当前仓库本地脚本 [render_local_paired_video_yolo_obb.py](/home/liujuncheng/rgbt_uav_detection/scripts/render_local_paired_video_yolo_obb.py) 里是按：

- `xywhr`
- `angle_rad`

来处理的，最终再转成角度展示。

前端应优先按：

- 原始 `angle` 为弧度

去验证。

如果前端按角度制直接解，框方向会异常。

### 检查 7：确认阈值

建议先用下面这组：

- `conf = 0.25`
- `iou = 0.5`
- `max_det = 300`

如果前端当前阈值过低，例如：

- `conf <= 0.05`

则即使逻辑正确，框数也会明显增多。

---

## 3. 建议的正确处理顺序

前端后处理建议严格按下面顺序执行：

1. 取出 `output0`
2. 打印形状
3. 若为 `[1, 10, 8400]`，先转成 `[8400, 10]`
4. 逐候选解析：
   - `cx, cy, w, h, angle`
   - `class_scores`
5. 对每个候选只保留：
   - `class_id = argmax(class_scores)`
   - `confidence = max(class_scores)`
6. 用 `confidence >= conf_threshold` 先筛一遍
7. 把候选框解成：
   - `xywhr`
   或
   - `polygon`
8. 对解码后的框做 NMS
9. 截断到 `max_det`
10. 再给前端渲染

---

## 4. 快速判断是不是前端逻辑错了

如果出现下面任意一种现象，基本就能判定是前端解码或 NMS 有问题：

1. 原始候选 `8400` 很正常，但筛选后仍上千
2. NMS 后还有 `1925`
3. 同一目标附近出现大量方向相似的小框
4. 不同类别标签在同一位置重复出现
5. 框方向明显不对，像“扇形散开”
6. 画出来的框远远超过画面里可见目标数

---

## 5. 给前端的最短结论

可以直接发给前端同学这句话：

> 当前 `YOLO-OBB` 模型的 `output0` 是原始候选输出，`8400` 对应 640 输入下三层特征图的候选点总数，不是最终框数。前端必须先把输出转成逐候选格式，再对每个候选只保留最大类别分数，解码为 `xywhr / polygon` 后再做 NMS；如果做完这些后还有 `1925` 个框，说明前端后处理口径仍然不对。
